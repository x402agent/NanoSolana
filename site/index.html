// What Ships

Everything in one binary.

No microservice sprawl. One npm i nanosolana and you have a full autonomous trading agent stack.

🔄

OODA Trading Engine

Observe → Orient → Decide → Act loop with Helius RPC ingestion, Birdeye market data, and Jupiter swap execution. RSI, EMA, and custom signal strategies.

🧠

ClawVault Memory

3-tier epistemological memory — Known, Learned, Inferred. AES-256-GCM encrypted persistence. The agent remembers, reasons, and evolves.

🥚

TamaGOchi Lifecycle

Egg → Larva → Juvenile → Adult → Alpha → Ghost. Your agent evolves based on on-chain performance. Feed it trades, watch it grow.

🔐

Encrypted Vault

AES-256-GCM local vault under ~/.nanosolana/vault.enc. HMAC-SHA256 gateway auth with timing-safe signature verification.

🌐

Mesh Networking

Gateway server with WebSocket support plus Tailscale-backed mesh for multi-agent swarms. Spawn, attach, and orchestrate bot fleets via tmux.

🎫

On-Chain Identity

Devnet NFT-based agent registration via Metaplex-compatible minting. Your agent gets a birth certificate on Solana.

CLI Reference

Every command available via nanosolana <command> or npx nanosolana <command>.

⚡ Core Runtime

nanosolana initPrompt for credentials and save them to the encrypted vault
nanosolana birthCreate or load the agent wallet and initialize the local TamaGOchi
nanosolana runStart wallet heartbeat, ClawVault, trading engine, and gateway
nanosolana goFull one-shot flow: configure → birth → run → scan → register
nanosolana demoSimulation mode with synthetic prices — no API keys needed
nanosolana statusShow wallet, pet, memory, gateway, Tailscale, and tmux summary
nanosolana petPrint the current TamaGOchi status display

🔍 Ops & Inspection

nanosolana registerMint the devnet on-chain identity NFT

// Programmatic

SDK Usage

Import any module directly. Build custom agents, strategies, or integrations on top of the NanoSolana stack.

import { ClawVault, NanoWallet, TamaGOchi, TradingEngine, loadConfig, } from "nanosolana"; const config = loadConfig(); // Create and initialize the wallet const wallet = new NanoWallet("my-agent"); await wallet.birth(); // Start the autonomous memory engine const vault = new ClawVault(); vault.startAutonomous(); // Birth the TamaGOchi companion const pet = new TamaGOchi("MyPet"); pet.recordWalletCreated(wallet.getInfo().balance); // Wire up the OODA trading engine const engine = new TradingEngine(config, wallet); engine.on("signal", (signal) => { console.log(`${signal.type} ${signal.symbol} ${(signal.confidence * 100).toFixed(0)}%`); }); await engine.start();

// Environment

Configuration

Secrets can come from the encrypted vault, environment variables, or both. nanosolana init writes defaults to .env and secrets to the vault.

OPENROUTER_API_KEY
AI Provider Key Required for live trading. Also accepts AI_API_KEY.
HELIUS_RPC_URL
Solana RPC Required for live mode, scans, and on-chain reads.
HELIUS_API_KEY
Helius API Key Required for live mode and blockchain scanning.
HELIUS_WSS_URL
WebSocket Endpoint Optional but recommended for real-time data streaming.
BIRDEYE_API_KEY
Market Data Optional in config, important for richer trading signals.
JUPITER_API_KEY
Swap Execution Required for live execution through Jupiter aggregator.
NANO_GATEWAY_SECRET
HMAC Secret Strongly recommended. Shared secret for gateway auth.
NANO_VAULT_PASSWORD
Vault Password Override vault password for deterministic multi-session setups.
TAILSCALE_AUTH_KEY
Mesh Networking Needed for automated Tailscale mesh enrollment.

Install

Four paths to running your first agent. Zero-config demo mode requires nothing but Node 22+.

1 Run Without Installing

npx nanosolana demo
npx nanosolana go

2 Global npm Install

npm install -g nanosolana
nanosolana demo

3 Shell Installer

curl -fsSL https://nanosolana.com/install.sh | bash
export PATH="$HOME/.nanosolana/bin:$PATH"
nanosolana go

4 From Source

git clone https://github.com/x402agent/NanoSolana.git
cd NanoSolana/nano-core && npm install
npm run build && node dist/cli/entry.js demo
// Trust Model

Security

Defense in depth from the vault to the wire. Every secret encrypted, every gateway call signed, every surface rate-limited.

🔒

AES-256-GCM Vault

All secrets stored in ~/.nanosolana/vault.enc with authenticated encryption. Local-machine oriented password by default.

✍️

HMAC-SHA256 Auth

Gateway signatures use HMAC-SHA256 with constant-time comparison via crypto.timingSafeEqual. No timing side-channels.

🛡️

Rate Limiting

HTTP and WebSocket surfaces are rate-limited per source address. No unauthenticated flood vectors.

⚠️

Devnet Only

On-chain registration uses Solana devnet. Do not treat devnet identity as production custody or compliance infrastructure.

🧪
Experimental Software

The trading engine is experimental. Start with demo mode, then a burner wallet, then very small live balances. Never risk funds you can't afford to lose.
